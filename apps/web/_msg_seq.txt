feat(cmd): compound commands (multi-step sequences)

支持「附能量到后备1 然后结束回合」这类**组合指令**一次提交多步。

engine:
- commands.split_sequence：按「然后/接着/之后/再/;/；/换行」切分；
  箭头 `→` 仅在「强分隔词没切开」且其后每段都以动词别名开头时才兜底切分，
  避免把指令 label 内部的「附能量 → 战斗位」误切成两步
- commands.sequence_hint / MAX_SEQUENCE_STEPS(=8)
- Battle.step_sequence(text|list, actor, max_steps)：**逐步按最新 legal_actions
  重新解析**并执行；语义：
    · 某步解析失败/引擎拒绝 → 停止，已执行动作保留（不回滚）
    · 回合移交（结束回合等）→ 停止，剩余步骤计入 remaining（不替对手走棋）
    · 对局结束/非主阶段/超步数上限 → 停止并说明原因
- tests +14 → engine 135/135

api:
- ActionReq 增 commands（显式步骤数组）；command 支持组合串
- POST /battles/{id}/actions：
  · 首步非法 → **422 且整单不执行**（避免"半执行 + 422"的歧义），
    detail 含 steps / hint / candidates / legal
  · 后续步骤失败 → **200 + 部分执行**，返回 steps[] / executed / planned /
    remaining / stopped（如实回报，不掩盖已生效的动作）
  · 响应形状统一：单步也是 steps 长度为 1
- 返回 sequence_hint 供前端提示
- tests +8 → api 61/61

web:
- src/sequences.js：前端**预览**切分（与引擎同规则；仅用于提示，真实解析以后端为准）
- CommandBar：输入组合句时实时显示「将按顺序执行 N 步：A → B」；
  BattlePage 日志逐步记录 `[1/2] …` `[2/2] …`，并在停止时输出
  「停止：<原因>（剩余 N 步：…）」
- styles：.seq-step（步骤胶囊）
- 新增 seq_e2e.cjs：真实 Chrome **6/6 PASS**（组合预览步数 → 逐步日志 [1/2][2/2]
  → 首步非法拒绝并给候选 → 回合移交停止并报告剩余步骤）
