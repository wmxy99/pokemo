## 第 3 层 · 端到端（greedy 输出对照）

6 条固定 prompt · 贪心解码 · max_new_tokens=64

**验收口径**：量化可以改变措辞（`exact_match` < 1 属正常），但**不应让答案变差** → 以「量化档正误**不差于** bf16 参考」为准。

| 用例 | 完全一致 | 归一一致 | 字符相似度 | 量化正误 | 参考正误 | 判据 |
|---|---:|---:|---:|:--:|:--:|---|
| dmg_weakness | ✗ | ✗ | 0.8444 | ✓ | ✗ | 答『翻倍/2倍』 |
| ko_prize | ✓ | ✓ | 1.0 | ✗ | ✗ | 答『2 张』（答 3 张为错） |
| poison_dmg | ✓ | ✓ | 1.0 | ✗ | ✗ | 答『10 点』 |
| k2_simple | ✗ | ✗ | 0.9573 | ✗ | ✗ | JSON 数组中含数值字段 30（复述不算通过） |
| k2_coin | ✓ | ✓ | 1.0 | ✗ | ✗ | JSON 数组中含数值字段 20（复述不算通过） |
| k2_draw | ✓ | ✓ | 1.0 | ✗ | ✗ | JSON 数组中含数值字段 2（复述不算通过） |

- 完全一致率 **0.667** · 归一化一致率 **0.667** · 字符相似度均值 **0.967**
- 正误计数：量化 **1/6** · 参考 **0/6** · 差值 **1**（无退化）　→ 验收（量化档**不差于**参考）**PASS ✅**

> **为什么验收是「不差于」而不是「必须一致」**：实测出现过差值 **+1**——量化档答对、bf16 参考答错（弱点题：量化答「翻倍」，参考答「增加 50%」）。这类分歧发生在模型**知识边界**附近，int8 的微小数值差异会翻转择优结果，方向可正可负。把它当作 FAIL 是误判；**只有差值为负（量化档变差）才是精度退化**。

**正误分歧用例（需人工确认是否量化所致）**：
- `dmg_weakness`：量化 ✓ / 参考 ✗

> **注意（阅读本表时的关键前提）**：`ko_prize`, `poison_dmg`, `k2_simple`, `k2_coin`, `k2_draw` 在**两档下都答错**——量化档与 bf16 参考**错得一模一样**，说明这是 **Qwen3-4B 自身的领域知识/指令遵循短板，与量化无关**。对本报告而言，这类用例的价值恰恰是「证明量化没有改变行为」；它们不构成「量化导致精度下降」的证据。

## 结论（三层验收汇总）

| 层 | 验收口径 | 结果 |
|---|---|---|
| 1 · 权重级 | 相对 Frobenius 误差 < 5% 且余弦 ≤ 1 | **PASS ✅**（0.0101）|
| 2 · 困惑度 | PPL 相对退化 < 1% | **PASS ✅**（-0.147%）|
| 3 · 端到端 | 量化档正误**不差于** bf16 参考 | **PASS ✅**（1 vs 0）|

**总体判定：通过 —— 8bit 未造成可测的精度退化 ✅**

> **关于「两档都答错」的用例**：第 3 层里有用例在**量化档与 bf16 参考下都答错**（如奖赏卡张数、中毒伤害点数）。两档错得一模一样 → 属 **Qwen3-4B 的领域知识/指令遵循短板，与量化无关**。这类用例对本报告的价值恰恰是「证明量化没有改变行为」。**但它们同时是产品风险信号**：若 K2 结构化抽取准确率不达标，应触发 ADR-LLM-001 的「K2 不达标切云端保底」分支。
